# Лаборатория Star Racing

В Unity Editor действует режим автора: профильный индекс и релизные отметки читаются из этого tracked-каталога. Любой standalone Player работает в режиме игрока: каталог поставки в Resources защищён, свои профили лежат отдельно в `Application.persistentDataPath/design-lab`. Полномочия задаёт код сборки, поле JSON их не меняет.

`index.json` хранит ID/имена, доступные версии, даты и отдельные релизные отметки. `<profile UUID>/<номер>.json` — полная неизменяемая версия баланса v8. `Default@1` побайтно совпадает с исходным `Resources/balance-config.json`; исходные значения и его hash сохранены. Дата старой версии неизвестна и остаётся null.

Новая версия публикуется отдельным файлом, затем атомарно заменяется индекс. `writer.lock` обеспечивает один writer; hash прочитанного индекса обнаруживает устаревшую запись. Оставшийся после ошибки orphan резервирует номер и не перезаписывается. Версии отдельно не удаляются; удаление своего дополнительного профиля удаляет его историю целиком. Основной Default в Editor и весь пакет в Player защищены от удаления.

Сохранение из Editor записывает файлы сюда и показывает назначение. Это не Git commit/push. При сохранении авторской работы нужно отдельно добавить индекс и созданные файлы версий в Git. Релизная отметка не запускает сборку и публикацию.

При явно заказанной сборке `DesignLabPackaging` проверяет наличие последней отмеченной версии Default и экспортирует только отмеченные версии в `Resources/DesignLabCatalog.json`. Повреждённые авторские файлы блокируют экспорт. Этот callback сам не запускает build. Проверки текущей фичи Player не собирают.

При запуске/reset выбирается последний отмеченный Default, независимо от прошлой сессии. Выбор и сохранение валидной версии активируют следующую гонку. Черновик, активная сохранённая версия и snapshot начатого матча разделены. Повтор не захватывает новый выбор.

Каталог: 3 поля движения, 11 руления/дрифта, 6 нитро и 3 AI. Метаданные и шаги в `LabParameters`; диапазоны общие с `ReleaseBalance`. 27 неиспользуемых handicap/contact/track полей сохраняются в payload, но не редактируются и не появляются в поиске/diff. Настройки предпочтений и обычная подготовка гонки остаются отдельными функциями.

Старой версии добавляются только отсутствующие поля из текущего релизного Default, без перезаписи исходного файла. Явные нули сохраняются. Неизвестные поля, схема, типы, диапазоны, шаги и отношения вроде nitroMaxSpeed >= baseSpeed проверяются до активации. Несовместимая версия остаётся в истории с ошибкой; можно вернуться к релизному Default.

Тихая QA: `tools/unity.sh shared -batchmode -noaudio -muted -executeMethod StarRacingPrototype.DesignLabPlayModeChecks.Run -logFile <absolute log>` с `STAR_RACING_LAB_QA_DIR=<new owned directory>`. Нужна отдельная человеческая приёмка физического ввода и Player. Pure C# contracts запускаются из `tests/design-lab`: `STAR_RACING_LAB_QA_DIR=<new directory> dotnet run --project LabContracts.csproj` (SDK из local global.json).
