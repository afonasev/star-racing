# Automatic GitHub installer links

Source baseline: main `ef018c86e1bd1792afc43a3b423bcb7418d15f86`. Owner: current installer-link task, branch `codex/auto-installer-links`.

`Installer download links` runs on published releases and default-main README/source-snapshot pushes. It reads complete GitHub release metadata and chooses the highest stable native SemVer with uploaded Windows EXE and macOS DMG (or PKG). Drafts, prereleases, incomplete pairs and JSON channel pointers are excluded. Only managed download blocks change; existing prose, canonical bilingual headings, assets, signatures, channels and Latest settings remain intact. Historical native releases link their own installers; technical content/shell notes and README link the current native version.

Source exports must retain `.github/workflows/installer-downloads.yml` and `.github/scripts/installer_downloads.py`; they are committed to this code project and published separately to GitHub. Bricks War exports explicitly include these files and retain the existing published download block. About uses the publisher-maintained stable `/releases/latest` address to survive major-version changes.

Manual recovery: run this workflow with `apply=false` for an audit or `apply=true` to reconcile. It is idempotent, retries README SHA conflicts while preserving new authored text, serializes jobs and fails visibly on API/inventory/readback errors. GITHUB_TOKEN writes do not recurse into push workflows. Each supported publisher explicitly dispatches this workflow after verified publication (including the Spacewars resume receipt path), so it also works when GitHub suppresses release events originating from GITHUB_TOKEN. Publisher credentials need workflow-dispatch access; CI publisher jobs using GITHUB_TOKEN must grant actions:write. The installer-link workflow itself only needs contents:write. Re-dispatch retries metadata reconciliation without rebuilding installers. An external source push with a skip-ci marker similarly needs explicit dispatch. No scheduled polling, game build or payload re-download is added.

Affected checks chosen before implementation: actual script mocked REST state transitions for all seven repositories, overwrite/retry/conflict/failure and native selection/preservation; workflow YAML/schema checks; Bricks exporter focused tests; focused real GitHub workflow dispatch audit/apply and metadata readback. Full game tests, builds, physical installs and a next real new-game release event are NotRun.
